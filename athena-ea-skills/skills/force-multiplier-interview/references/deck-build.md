# Stages 6-8 — Synthesis, pressure test, deck

## Stage 6 — Synthesize

Triggered when the user says "synthesize," or when every branch is settled.
Stop interviewing. Return:

1. **The strongest claim**, in one sentence.
2. **Three proof points**, each with its number, where the number came from,
   and — if a reconciliation ran — which figure they chose.
3. **Core Values** — one incident per value, one line each. Name explicitly
   any value that couldn't be evidenced.
4. **Wellness & Development** — strongest item, one line.
5. **Advocacy & Impact** — strongest item, one line.
6. **The weakest part of the case**, and the fix.
7. **Three likeliest objections**, with the best answer to each.
8. **Every open gap** — numbers still owed.

Store it in the vault and put the gaps in state, where next cycle finds them
first. Read it back and confirm before reporting saved.

**Have the EA correct the synthesis before building anything.** They know
their work better than the transcript does.

## Stage 8a — Choose a build path

Ask before generating. Don't assume.

| Path | When | Watch for |
|---|---|---|
| Design artifact / canvas | No mandated template; wants polish fast | Confirm Athena accepts a shared link, or that export works |
| Copy for Slides / PowerPoint | Athena supplies a template | Most manual, safest for format compliance |
| Generated `.pptx` | A real file must be uploaded or emailed | Check it opens cleanly before submitting |
| In-app assistant (Claude for PowerPoint) | Already iterating inside PPT | Requires the add-in |

**Rule of thumb:** template provided → write copy for their template.
No template → build the artifact and export.

## Stage 8b — Deck structure

Target 10–13 slides. The three rubric sections should be visibly distinct —
a reviewer scoring against the rubric shouldn't have to hunt.

| Slide | Content |
|---|---|
| 1 | Title — name, account, period covered |
| 2 | The one-sentence claim |
| 3 | Baseline — where things stood at the start |
| **Performance** | |
| 4–6 | One proof point per slide: the number, its source, what it enabled |
| 7 | The multiplier — what the client produced with returned capacity |
| 8 | Scope growth — then vs. now, two columns |
| 9 | Beyond the client — assets built, EAs taught |
| 10 | Core Values — one incident per value, one line each |
| **Wellness & Development** | |
| 11 | Learning and sustainable practice |
| **Advocacy & Impact** | |
| 12 | Community or personal advocacy |
| **Close** | |
| 13 | What they'll own next — the trajectory, not a request |

**Headlines are claims, not labels.** "Calendar admin down 84%" beats
"Calendar Management." A reviewer should get the case from headlines alone.

**Slide 10 is one slide, not four.** Four incidents, one line each. If a
value has no incident, omit it silently — an empty row draws more attention
than an absent one.

**If a figure came from mined history, the slide should be able to say
where.** Not a citation on the slide, but the EA should know the answer
before they're asked.

## Stage 8c — Cut

Ask yourself which slide is weakest and tell them to cut it. A tight eleven
beats a padded fifteen. Then store the copy.

## Stage 7 — Pressure test

**Runs before the deck, not after.** Two mock panels, five hardest questions
each, one at a time, with a verdict on every answer. The second run is
measurably better than the first, which is why there are two.

What breaks here gets fixed in the synthesis before a single slide exists.

Weight the questions toward:

- Any figure where the estimate and the record diverged
- Any claim resting on a "not found" row
- The floor caveat: "is that everything you did?"
- "Isn't this just the job description done well?"
- "What here couldn't another EA have done?"
